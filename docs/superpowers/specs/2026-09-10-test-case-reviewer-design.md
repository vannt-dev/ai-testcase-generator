# Test Case Reviewer / Coverage Checker — Design

Status: approved (design), pending implementation plan
Roadmap: Phase 2 of the project roadmap (README.md)

## Purpose

Let a tester check whether a set of test cases (either just generated by
this tool, or written elsewhere and uploaded) adequately covers a
requirement and a project's config — before it's considered done. The
AI reports a coverage score, missing test types, specific gaps, and
duplicate/redundant cases, and can generate test cases to fill the
identified gaps on request.

## Scope

**In scope:**
- A new Streamlit page (`pages/1_Reviewer.py`) reachable from the sidebar nav.
- Reviewing test cases from the current session's last generation result.
- Reviewing test cases uploaded as an arbitrary `.xlsx`/`.csv` file, with
  AI-assisted column mapping confirmed by the user.
- Coverage scoring against: the original requirement text, the project's
  `test_types_required`/`domain_rules` config, and duplicate detection.
- Generating missing test cases for identified gaps, on demand, in the
  same schema as the Generator page so they can be merged and exported.

**Out of scope (future phases, not part of this spec):**
- Bug Report Writer / Jira integration (Phase 3).
- Automation / self-healing test code generation (Phase 4).
- Persisting review results outside the current browser session.
- Reviewing formats other than `.xlsx`/`.csv` (e.g. PDF, plain text paste).

## Architecture

Convert to a Streamlit multipage app using the standard convention:
- `app.py` stays as-is and becomes the "Generator" (home) page — no
  changes needed to how it's launched (`streamlit run app.py`).
- `pages/1_Reviewer.py` is added; Streamlit auto-discovers it and lists
  it in the sidebar nav, ordered by the numeric filename prefix.
- Shared session state (`config` selection is per-page, but
  `st.session_state["last_result"]` / `last_project_name` set by the
  Generator page are readable from the Reviewer page — Streamlit session
  state is shared across pages in the same session).

New modules:
- `core/file_import.py` — parses an uploaded `.xlsx`/`.csv` into raw rows
  (list of dicts keyed by the file's own column headers). Format-agnostic;
  has no knowledge of the `TestCase` schema.
- `prompts/reviewer_system_prompt.md` — system prompt for the coverage
  review role.
- `prompts/column_mapping_system_prompt.md` — system prompt for the
  column-mapping suggestion call.

Extended modules:
- `core/ai_client.py` — two new `AIClient` methods and their Pydantic
  schemas (see below), reusing the existing retry/error-handling logic
  already in `generate_test_cases`.

## Components

### `pages/1_Reviewer.py`

Two input modes, presented as tabs:

1. **"From current session"** — reads `st.session_state["last_result"]`
   and the currently selected project config. Disabled/hidden with a
   hint message if no generation has happened yet this session.
2. **"Upload external file"** — `st.file_uploader` (`.xlsx`, `.csv`), a
   project `st.selectbox` (reuses `list_available_configs`), and a
   `st.text_area` for the requirement text the uploaded cases should be
   checked against.

For the upload path: after parsing, an AI call suggests a mapping from
the file's columns to the `TestCase` fields. The mapping is rendered as
one `st.selectbox` per required field (`test_id`, `module`, `title`,
`precondition`, `steps`, `test_data`, `expected_result`, `priority`,
`type`, `platform`), pre-filled with the AI's suggestion but always
user-editable. The "Review Coverage" button stays disabled until every
required field has a non-empty mapping selected.

Once `requirement_text` + `config` + `test_cases` (normalized to the
`TestCase` shape) are available from either path, "Review Coverage"
calls `review_test_cases()` and renders a `ReviewResult`:
- `coverage_score` as an `st.metric` (0-100).
- `missing_test_types` as a list of tags/badges.
- `gaps` as an expandable list, color-coded by `severity` (reusing the
  High/Medium/Low color convention from `excel_exporter.PRIORITY_COLORS`).
- `duplicates` as grouped `test_id` lists with the AI's stated reason.

A **"Generate missing cases"** button (enabled when `gaps` is non-empty)
calls `generate_missing_cases()`, passing the gap list. Results render
in their own `st.data_editor` (same column config as the Generator
page) for review/editing before merging. A **"Merge into main set"**
button appends the accepted rows into the working `test_cases` list,
resolving `test_id` collisions by appending `_2`, `_3`, etc. After a
merge, the existing `export_to_excel` (unchanged) is available to
download the combined set.

### `core/file_import.py`

```python
def parse_uploaded_file(uploaded_file) -> list[dict]:
    """
    Parse an uploaded .xlsx/.csv (a Streamlit UploadedFile) into a list
    of dicts keyed by the file's own column headers. Raises
    FileImportError (a ValueError subclass) with a user-facing message
    on an unsupported extension, an empty/unreadable file, or more than
    MAX_IMPORTED_ROWS rows.
    """
```
`MAX_IMPORTED_ROWS = 500` (mirrors the spirit of `app.py`'s
`MAX_REQUIREMENT_CHARS` cap — keeps the review prompt within a
reasonable token budget).

### `core/ai_client.py` additions

New Pydantic schemas:

```python
class CoverageGap(BaseModel):
    description: str = Field(min_length=1)
    suggested_type: Literal[
        "Positive", "Negative", "Edge case", "UI/UX",
        "Compatibility", "Performance", "Security",
    ]
    severity: Literal["High", "Medium", "Low"]

class DuplicateGroup(BaseModel):
    test_ids: list[str] = Field(min_length=2)
    reason: str = Field(min_length=1)

class ReviewResult(BaseModel):
    coverage_score: int = Field(ge=0, le=100)
    missing_test_types: list[str]
    gaps: list[CoverageGap]
    duplicates: list[DuplicateGroup]
    summary_note: str

class ColumnMappingResult(BaseModel):
    mapping: dict[str, str]  # our field name -> uploaded column name (or "" if unmatched)
```

New `AIClient` methods (same retry/error-handling pattern as
`generate_test_cases`, reusing `_sleep`/`max_retries`/pricing tracking):

```python
def review_test_cases(self, system_prompt: str, requirement_text: str, test_cases: list[dict]) -> dict:
    """Returns {"review": ReviewResult-shaped dict, "usage": {...}}."""

def generate_missing_cases(self, system_prompt: str, requirement_text: str, gaps: list[dict]) -> dict:
    """Returns {"test_cases": [...], "usage": {...}} — same TestCase shape as generate_test_cases."""

def suggest_column_mapping(self, headers: list[str], sample_rows: list[dict]) -> dict:
    """
    sample_rows: the first 5 parsed rows (enough context for the AI to
    guess column semantics without inflating the prompt on large files).
    Returns {"mapping": {...}} — best-effort guess, always user-confirmed
    before use.
    """
```

`prompts/reviewer_system_prompt.md` is built the same way as the
existing base prompt: merged with the project's config context via a
reused/adapted `build_system_prompt`-style helper, so `domain_rules`
and `test_types_required` are visible to the coverage check.

## Data Flow

1. User picks an input mode on the Reviewer page.
2. **Upload path only:** `parse_uploaded_file` → raw rows → `suggest_column_mapping` (AI) → user confirms/edits mapping in the UI → rows normalized into `TestCase`-shaped dicts.
3. Either path converges on: `requirement_text`, `config`, `test_cases`.
4. `review_test_cases()` → `ReviewResult` rendered in the UI.
5. Optional: `generate_missing_cases()` → new `TestCase` list → reviewed in a `data_editor` → merged into the working set (dedup `test_id`).
6. Export via the existing `export_to_excel`.

## Error Handling

- AI calls: identical error taxonomy to `generate_test_cases`
  (`AuthenticationError`, `RateLimitError`/`APIConnectionError` with
  retry, `APIStatusError`, `max_tokens` truncation, missing
  `parsed_output`) — all surfaced as the existing `ValueError` messages,
  caught by the page the same way `app.py` already does.
- Upload parsing: `FileImportError` (unsupported extension, empty/corrupt
  file, over `MAX_IMPORTED_ROWS`) shown via `st.error`, blocking further
  action.
- Column mapping: the "Review Coverage" button is disabled until every
  required `TestCase` field has a non-empty mapping — no silent guessing
  is acted upon without user confirmation.
- Merge: `test_id` collisions are resolved automatically with a numeric
  suffix rather than erroring.

## Testing

- `tests/test_file_import.py` — parses fixed sample `.xlsx`/`.csv`
  content into rows; covers the unsupported-format, empty-file, and
  over-row-limit error paths. No AI involved.
- `tests/test_ai_client.py` — extended with tests for
  `review_test_cases`, `generate_missing_cases`, and
  `suggest_column_mapping`, using the existing `FakeMessages` mock
  pattern.
- Schema tests for `ReviewResult`/`CoverageGap`/`DuplicateGroup`/
  `ColumnMappingResult` — valid input, missing required field, invalid
  enum value.
- `tests/test_reviewer_page.py` — `streamlit.testing.v1.AppTest` against
  `pages/1_Reviewer.py`, mocking the new `AIClient` methods, covering:
  session-sourced review, upload-sourced review with a confirmed
  mapping, the disabled-button state when required fields are unmapped,
  and the merge/export path.
